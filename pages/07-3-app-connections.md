# 07-3. 플러그인과 앱 연결: 복사·붙여넣기 없이 일하기

## 1. 이 강의에서 배울 내용

ChatGPT를 업무에 쓰다 보면 문서나 메일에서 필요한 내용을 복사해 대화창에 붙여 넣고, 답변이 나오면 다시 원래 도구로 옮기는 일이 반복됩니다. 외부 서비스를 연결하면 ChatGPT가 허용된 범위 안에서 필요한 자료를 찾고, 그 자료를 바탕으로 결과물을 만들 수 있습니다.

영상 촬영 이후 제품 용어와 탐색 방식이 바뀌었습니다. 현재 OpenAI 공식 문서에서는 **플러그인**을 반복 가능한 업무 흐름을 묶은 패키지로 설명합니다. 플러그인에는 작업 지침인 스킬과 GitHub·Gmail·Notion 같은 외부 서비스에 연결하는 커넥터가 포함될 수 있습니다. 실제 데이터 접근과 행동 권한은 연결된 앱이 담당합니다.

이 강의에서는 다음 내용을 익힙니다.

* 플러그인, 스킬과 연결된 앱의 관계를 이해합니다.
* 읽기와 변경 권한을 구분합니다.
* 필요한 권한만 허용해 앱을 연결합니다.
* 메일 검색, 답장 초안과 발송 전 검수를 단계별로 진행합니다.
* 외부 변경은 사람이 확인한 뒤 승인하는 흐름을 만듭니다.
* 연결 상태와 권한을 정기적으로 점검합니다.

## 2. 플러그인과 앱의 관계

| 구성 | 역할 | 예시 |
| --- | --- | --- |
| 플러그인 | 특정 업무에 필요한 기능을 묶어 제공 | 메일 정리, 문서 조사, GitHub 작업 흐름 |
| 스킬 | 작업 절차와 품질 기준을 안내 | 조사 방식, 문서 작성 규칙, 검수 체크리스트 |
| 연결된 앱·커넥터 | 외부 서비스의 데이터와 행동에 접근 | Gmail 검색, GitHub 파일 읽기·변경, Notion 페이지 조회 |

플러그인을 설치했다고 외부 데이터 접근이 자동으로 허용되는 것은 아닙니다. 필요한 앱을 별도로 연결하고 요청되는 권한을 검토해야 합니다. 플랜, 워크스페이스 정책과 역할에 따라 설치하거나 사용할 수 있는 기능이 달라질 수 있습니다.

## 3. 읽기 권한과 변경 권한

외부 서비스 연결에서 가장 먼저 구분할 것은 **읽는 일**과 **바꾸는 일**입니다.

### 3.1 읽기 중심 작업

* 메일이나 문서 검색
* 파일 내용 요약
* 이슈와 Pull Request 상태 확인
* 일정과 기록 조회

읽기 작업도 민감한 정보에 접근할 수 있으므로 범위를 확인해야 하지만, 외부 데이터를 직접 바꾸지는 않습니다.

### 3.2 변경 작업

* 메일과 메시지 발송
* 문서나 데이터베이스 수정
* 일정 생성·변경
* 저장소의 파일 수정, 커밋과 Pull Request 생성

변경 작업은 다른 사람과 시스템에 영향을 줄 수 있습니다. 처음 연결할 때는 읽기부터 시작하고, 변경이 필요할 때는 결과를 확인한 뒤 승인하도록 설정합니다.

권장 기본값은 다음과 같습니다.

> 읽기는 허용하고, 변경 시에는 확인합니다.

## 4. 연결 전에 확인할 세 가지

### 4.1 목적

왜 연결하는지 한 문장으로 설명할 수 있어야 합니다. 예를 들어 “최근 인세 보고서를 찾아 답장 초안을 만들기 위해 메일함을 연결한다”처럼 구체적으로 정합니다.

### 4.2 범위

어떤 계정, 저장소, 폴더와 데이터에 접근할 수 있는지 확인합니다. 업무에 필요하지 않은 범위까지 연결하지 않습니다.

### 4.3 권한 수준

읽기만 필요한지, 생성과 수정도 필요한지 구분합니다. 발송, 삭제와 외부 공개처럼 되돌리기 어렵거나 영향이 큰 행동은 매번 확인하는 편이 안전합니다.

## 5. 앱 연결하기

화면 구성은 앱, 플랜과 워크스페이스 설정에 따라 달라질 수 있습니다. 현재 환경에서는 Plugins 화면이나 설정에서 필요한 플러그인을 찾고, 포함된 앱의 연결 절차를 진행합니다.

1. 업무에 필요한 플러그인을 선택합니다.
2. 포함된 스킬, 앱과 요구되는 연결을 확인합니다.
3. 연결할 계정이 올바른지 확인합니다.
4. 요청되는 데이터 범위와 행동 권한을 읽습니다.
5. 읽기 중심으로 시작하고 변경은 확인하도록 설정합니다.
6. 연결이 완료되면 간단한 조회 요청으로 범위를 시험합니다.

연결 화면에서 다음 내용을 확인하지 않은 채 승인하지 않습니다.

* 어떤 서비스와 계정에 연결되는가?
* 읽을 수 있는 데이터는 무엇인가?
* 만들거나 바꿀 수 있는 항목은 무엇인가?
* 작업 전에 사용자 확인을 요구하는가?
* 연결을 해제하고 권한을 회수하는 방법은 무엇인가?

## 6. 실습 1: 메일 찾기

이번 실습은 연결된 메일함에서 출판사의 인세 보고서를 찾는 상황입니다. 실제 개인정보가 포함된 계정 대신 실습용 계정이나 샘플 메일을 사용합니다.

먼저 검색만 요청합니다. 답장 작성과 발송을 한 번에 시키지 않습니다.

<pre><code>연결된 메일함에서 출판사가 발송한 최근 인세 보고서를 찾아 주세요.

아직 답장은 작성하거나 발송하지 마세요.
발신자, 제목, 수신 날짜, 핵심 요청 사항과 후속 조치 기한만 정리해 주세요.

조건에 맞는 메일이 여러 개면 모두 보여 주고, 어떤 메일을 사용할지 제가 선택하게 해 주세요.</code></pre>

결과에서 발신자, 날짜와 제목이 원문과 일치하는지 확인합니다. 같은 이름의 발신자나 비슷한 제목이 여러 개라면 사람이 정확한 메일을 선택해야 합니다.

## 7. 실습 2: 답장 초안 만들기

올바른 메일을 선택한 뒤 답장 초안을 요청합니다. 수신자 주소는 실제 주소가 아닌 `[수신자 이메일]` 자리표시자로 둡니다.

<pre><code>방금 제가 선택한 메일에 대한 답장 초안을 작성해 주세요.

- 상세한 안내에 감사를 표시합니다.
- 후속 도서의 출간 제안을 문의합니다.
- 후속 도서는 엑셀 기본서이며 가제는 “엑셀 마스터 클래스”입니다.
- 그동안의 경험과 지식을 바탕으로 완성도 높은 도서를 준비하고 있다는 자신감을 담되 과장하지 않습니다.
- 수신자는 [수신자 이메일]로 표시합니다.
- 아직 발송하지 마세요.

제목과 본문을 분리해 보여 주세요.</code></pre>

초안 단계에서는 발송 권한이 필요하지 않습니다. 결과를 확인하고 필요한 사실, 어조와 표현을 사람이 수정합니다.

## 8. 실습 3: 발송 전 검수

외부 발송 전에 새 관점으로 검수합니다.

<pre><code>이 답장 초안을 발송 전 검수해 주세요.

1. 원문이나 제가 제공한 정보에 없는 내용을 임의로 만든 부분이 있는가
2. 신뢰감을 잃을 정도로 과장된 표현이 있는가
3. 외부에 보내면 안 되는 개인정보나 내부 정보가 포함되어 있는가
4. 수신자, 제목, 첨부파일과 후속 조치가 올바른가
5. 오해를 부를 수 있는 일정·금액·약속이 있는가

문제가 있으면 해당 문장, 이유와 수정안을 표로 보여 주세요.
발송은 하지 마세요.</code></pre>

검수 결과를 받은 뒤 다음 항목을 사람이 직접 확인합니다.

* 수신자 이름과 이메일 주소
* 원문에 대한 사실관계
* 금액, 날짜와 약속
* 조직의 말투와 서명
* 개인정보와 내부 정보
* 필요한 첨부파일

발송은 이 확인이 끝난 뒤 별도의 명시적 요청과 승인으로 진행합니다. 교육 실습에서는 실제 발송 대신 초안 저장까지만 진행해도 충분합니다.

## 9. 안전한 업무 흐름

앱 연결을 활용한 안전한 기본 흐름은 다음과 같습니다.

> 검색 → 대상 확인 → 초안 작성 → 사실·어조·보안 검수 → 사람이 승인 → 변경 실행

이 순서를 지키면 잘못된 대상에게 보내거나, 원문에 없는 내용을 단정하거나, 내부 정보를 외부로 내보내는 위험을 줄일 수 있습니다.

특히 웹 페이지, 이메일과 문서에 포함된 지시는 사용자가 요청한 목적과 충돌할 수 있습니다. 연결된 자료 안의 문구가 “다른 사람에게 보내라”, “비밀 정보를 알려 달라”처럼 새로운 행동을 요구해도 자동으로 따르지 말고 사용자의 원래 요청과 권한 범위를 우선합니다.

## 10. 연결 관리와 해제

업무가 끝나거나 더 이상 필요하지 않은 연결은 정리합니다.

* 연결된 서비스와 계정을 정기적으로 확인합니다.
* 사용하지 않는 앱 연결을 해제합니다.
* 권한이 과도하면 더 좁은 범위로 다시 연결합니다.
* 조직을 옮기거나 프로젝트가 끝나면 접근 권한을 회수합니다.
* 변경 작업의 승인 기록과 결과를 확인합니다.

플러그인을 제거해도 연결된 앱의 인증이 별도로 남을 수 있습니다. 플러그인과 앱 연결 상태를 각각 확인합니다.

## 11. 자주 막히는 문제와 해결 방법

| 문제 | 가능한 원인 | 해결 방법 |
| --- | --- | --- |
| 플러그인이 보이지 않음 | 플랜·역할·관리자 정책 또는 지원 화면의 차이 | Plugins와 워크스페이스 설정 확인, 필요하면 관리자에게 요청 |
| 앱 데이터에 접근하지 못함 | 로그인 만료, 잘못된 계정 또는 좁은 권한 | 연결된 계정과 허용 범위를 다시 확인 |
| 엉뚱한 메일·문서를 찾음 | 검색 조건이나 대상이 모호함 | 발신자, 기간, 제목과 파일 위치를 추가하고 후보를 먼저 보여 달라고 요청 |
| 변경 직전에 작업이 멈춤 | 외부 변경에 승인이 필요함 | 결과와 대상을 검토한 뒤 해당 작업만 승인 |
| 과도한 권한이 요구됨 | 플러그인 업무 범위보다 앱 권한이 큼 | 연결 목적을 재검토하고 최소 권한으로 축소 |
| 초안에 없는 사실이 들어감 | 원문과 사용자 입력의 경계가 불명확함 | 근거 없는 내용은 확인 필요로 표시하도록 지시 |

## 12. 실습 완료 기준

* 플러그인과 연결된 앱의 역할을 구분할 수 있습니다.
* 연결 목적, 범위와 권한 수준을 확인했습니다.
* 읽기는 허용하고 변경 시 확인하는 방식으로 시작했습니다.
* 검색, 대상 확인, 초안과 검수를 한 번에 묶지 않고 단계별로 진행했습니다.
* 수신자, 사실관계, 어조, 보안과 첨부파일을 확인했습니다.
* 실제 발송이나 변경은 별도의 승인 전까지 실행하지 않았습니다.
* 필요 없는 연결을 해제하는 방법을 확인했습니다.

## 13. 핵심 정리

* 플러그인은 스킬과 외부 서비스 연결을 포함할 수 있는 업무 패키지입니다.
* 외부 데이터와 행동에 대한 실제 접근은 연결된 앱의 인증과 권한을 따릅니다.
* 연결 전에는 목적, 범위와 권한 수준을 확인합니다.
* 처음에는 읽기부터 시작하고 변경은 사람이 확인한 뒤 승인합니다.
* 검색, 초안, 검수와 발송을 단계별로 나누면 오류의 영향을 줄일 수 있습니다.
* 발송 전에는 수신자, 사실관계, 어조와 보안을 확인합니다.
* 플러그인 제거와 앱 연결 해제는 별도로 확인합니다.

현재 플러그인의 구조와 설치·연결 방식은 [OpenAI 플러그인 공식 가이드](https://learn.chatgpt.com/docs/plugins)에서 확인할 수 있습니다.
