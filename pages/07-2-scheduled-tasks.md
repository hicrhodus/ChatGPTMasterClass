# 07-2. 일정·예약 작업으로 반복 업무 자동화하기

## 1. 이 강의에서 배울 내용

매일 뉴스를 확인하고, 매주 같은 형식으로 보고서를 만들고, 특정 변화가 생겼는지 반복해서 살피는 일은 중요하지만 사람이 매번 같은 요청을 다시 입력하기에는 비효율적입니다.

ChatGPT의 예약 작업은 프롬프트를 한 번 저장하고 정해진 시간이나 지원되는 이벤트에 맞춰 다시 실행하도록 만드는 기능입니다. 현재 공식 문서에서는 이 기능을 **Scheduled tasks**라고 설명하며, 화면의 한국어 명칭은 앱과 버전에 따라 ‘예약 작업’ 또는 ‘예약됨’처럼 표시될 수 있습니다.

이 강의에서는 다음 내용을 익힙니다.

* 일반 대화와 예약 작업의 차이를 이해합니다.
* 일회성, 반복, 모니터링 작업을 구분합니다.
* 실행 시점과 작업 지시를 분리해 설계합니다.
* 뉴스 모니터링 예약 작업을 만듭니다.
* 작업의 결과, 일정과 알림을 관리합니다.
* 실패하기 쉬운 조건과 보안 주의사항을 확인합니다.

## 2. 일반 대화와 예약 작업의 차이

일반 대화는 사용자가 요청을 보낼 때 실행됩니다. 예약 작업은 저장된 지시문을 미래의 시점, 반복 일정 또는 지원되는 이벤트에 따라 실행합니다.

| 구분 | 일반 대화 | 예약 작업 |
| --- | --- | --- |
| 시작 | 사용자가 요청을 보냄 | 정해진 일정·조건에 따라 실행 |
| 반복 | 같은 요청을 다시 입력 | 저장된 지시를 반복 실행 |
| 관리 | 해당 채팅에서 확인 | Scheduled 화면에서 상태와 실행 기록 확인 |
| 적합한 일 | 즉시 답이 필요한 작업 | 정기 요약, 알림, 변화 모니터링 |

자동화의 목적은 생각을 없애는 것이 아닙니다. 반복해서 시작 버튼을 누르는 일을 줄이고, 사람은 결과를 검토하고 판단하는 데 집중합니다.

## 3. 예약 작업의 세 가지 유형

### 3.1 일회성 작업

미래의 특정 시점에 한 번만 실행합니다.

* 내일 오후 회의 준비 알림
* 다음 주 계약 갱신 확인
* 특정 날짜에 제출 자료 점검

### 3.2 반복 작업

정해진 주기에 같은 종류의 작업을 실행합니다.

* 평일 아침 산업 뉴스 요약
* 매주 금요일 주간 업무 정리
* 매월 첫 영업일 지표 점검

### 3.3 모니터링 작업

정기적으로 상태를 확인하되 의미 있는 변화가 있을 때만 알려 달라고 요청합니다.

* 규정이나 정책 변경 확인
* 특정 제품의 업데이트 확인
* 공개 채용 공고의 신규 등록 확인

모니터링은 “매번 보고서를 보내 달라”가 아니라 “변화가 있을 때만 알려 달라”는 조건을 분명히 해야 불필요한 알림을 줄일 수 있습니다.

## 4. 좋은 예약 작업을 만드는 여섯 가지 요소

예약 시간만 정한다고 좋은 자동화가 되는 것은 아닙니다. 실제 결과를 좌우하는 것은 작업 지시의 품질입니다.

| 요소 | 확인할 질문 |
| --- | --- |
| 목적 | 왜 이 결과가 필요한가? |
| 일정 | 언제, 어떤 주기로 실행할 것인가? |
| 대상 | 무엇을 확인하거나 처리할 것인가? |
| 선별 기준 | 무엇을 포함하고 제외할 것인가? |
| 출력 형식 | 몇 개를 어떤 구조로 정리할 것인가? |
| 알림 조건 | 변화가 없을 때도 알릴 것인가? |

시간대가 중요한 작업은 지역과 시간대를 함께 확인합니다. “오전 8시”가 어느 지역의 시간인지 애매하면 실행 시각이 기대와 달라질 수 있습니다.

## 5. 실습: 평일 아침 AI 뉴스 브리핑 만들기

이번 실습의 목표는 평일 오전 8시에 주요 AI 업무 자동화 뉴스를 선별해 받는 작업을 만드는 것입니다.

<pre><code>매주 평일 오전 8시에 AI 업무 자동화 관련 주요 뉴스를 확인해 주세요.

다음 기준으로 정리해 주세요.

- 출처는 공식 발표, 주요 기술 매체, 제품 업데이트를 우선합니다.
- 기업 실무자에게 중요한 뉴스 5개만 선별합니다.
- 각 뉴스는 제목, 핵심 내용, 업무 활용 가능성, 출처 링크와 발표 날짜로 정리합니다.
- 같은 소식을 반복해서 포함하지 않습니다.
- 과장된 표현은 제외합니다.
- 한국어 마크다운 형식으로 작성합니다.

마지막에는 “오늘 확인해야 할 변화”를 3줄로 요약해 주세요.
새로운 내용이 없으면 억지로 채우지 말고 “중요한 변화 없음”이라고 알려 주세요.</code></pre>

작업 생성 화면에서 다음 내용을 확인합니다.

1. 지시문과 실행 일정이 의도대로 해석됐는가?
2. 평일과 주말이 올바르게 구분됐는가?
3. 오전 8시의 시간대가 맞는가?
4. 결과가 돌아올 채팅이나 위치가 맞는가?
5. 알림이 필요한 경우 알림 설정이 켜져 있는가?

계정, 플랜, 앱 버전과 워크스페이스 정책에 따라 지원 범위와 화면이 달라질 수 있습니다. 실제 생성 화면에 표시되는 일정과 권한을 기준으로 최종 확인합니다.

## 6. 첫 실행을 검수하는 방법

예약 작업을 만들었다고 자동화가 끝난 것은 아닙니다. 첫 몇 번의 실행 결과를 검토해 지시문을 조정합니다.

### 출처와 최신성

* 출처 링크가 실제로 열리는가?
* 발표 날짜가 요청한 기간에 맞는가?
* 공식 발표와 기사 내용을 구분했는가?
* 오래된 내용을 새로운 소식처럼 다시 포함하지 않았는가?

### 선별 품질

* 기업 실무자에게 중요한 내용이 우선됐는가?
* 서로 같은 사건을 다룬 기사들이 중복되지 않았는가?
* 선정 이유와 업무 활용 가능성이 구체적인가?

### 출력 형식

* 요청한 개수와 구조를 지켰는가?
* 링크와 날짜가 빠지지 않았는가?
* 변화가 없을 때 억지로 내용을 만들지 않았는가?

결과가 너무 넓으면 대상과 출처를 좁히고, 중요한 소식이 빠지면 검색 범위와 선정 기준을 보완합니다.

## 7. 작업 관리

현재 공식 안내에서는 Scheduled 화면에서 활성, 일시 중지, 완료된 작업과 최근 실행을 확인할 수 있습니다. 작업을 열어 다음 항목을 관리합니다.

* 제목과 지시문 수정
* 실행 일정 변경
* 일시 중지와 재개
* 실행 결과와 오류 확인
* 필요 없는 작업 삭제
* 알림 설정 확인

예약 작업의 수, 최소 실행 주기와 사용할 수 있는 모델은 플랜과 워크스페이스 설정에 따라 달라질 수 있습니다. 한도를 숫자로 외우기보다 현재 계정의 Scheduled 화면과 공식 안내를 확인합니다.

## 8. 연결된 앱과 이벤트 기반 작업

지원되는 환경에서는 Gmail, Slack 또는 GitHub 같은 앱의 이벤트를 계기로 작업을 실행할 수 있습니다. 예를 들어 특정 저장소의 Pull Request 활동을 검토하거나, 특정 조건의 새 메일이 왔을 때 내용을 분류할 수 있습니다.

이때는 다음 두 요소를 나눠 생각합니다.

* **트리거:** 어떤 사건이 작업을 시작하는가?
* **저장된 지시문:** 시작된 뒤 무엇을 확인하고 어떤 결과를 만드는가?

외부 데이터를 읽거나 변경하는 작업에는 연결 권한과 승인 절차가 적용됩니다. 특히 메시지 발송, 파일 수정과 저장소 변경처럼 외부에 영향을 주는 행동은 결과를 검토한 뒤 승인하도록 설정합니다.

## 9. 한계와 보안 주의사항

### 9.1 자동 실행과 정확성은 다릅니다

예약 작업은 프롬프트 실행을 자동화할 뿐 결과의 정확성을 보장하지 않습니다. 중요한 수치, 일정, 법률·재무·의료 관련 판단은 원문과 담당자를 통해 다시 확인합니다.

### 9.2 민감정보를 지시문에 넣지 않습니다

작업 제목, 지시문과 공유된 결과는 다른 사람이 볼 수 있는 환경에 노출될 수 있습니다. 비밀번호, 계정번호, 고객 개인정보와 회사 기밀을 넣지 않습니다.

### 9.3 필요한 권한만 사용합니다

처음에는 읽기와 초안 작성처럼 영향이 작은 범위로 시작합니다. 외부 시스템을 변경하거나 메시지를 보내는 작업은 승인 단계를 유지합니다.

### 9.4 실패해도 조용히 넘어가지 않게 합니다

자료에 접근할 수 없거나 출처를 확인하지 못했을 때 성공한 것처럼 결과를 만들지 않도록 지시합니다.

<pre><code>필요한 출처에 접근하지 못했거나 사실을 확인할 수 없으면 추정하지 마세요.
실패한 단계, 확인하지 못한 항목과 사용자가 해야 할 조치를 알려 주세요.</code></pre>

## 10. 자주 막히는 문제와 해결 방법

| 문제 | 가능한 원인 | 해결 방법 |
| --- | --- | --- |
| 작업이 생성되지 않음 | 계정·플랜·워크스페이스에서 기능이 지원되지 않음 | 현재 계정의 Scheduled 메뉴와 관리자 설정 확인 |
| 예상 시각과 다르게 실행됨 | 시간대나 반복 조건이 모호함 | 지역, 시간대, 요일과 예외 날짜를 명시 |
| 결과가 매번 너무 많음 | 선별 기준과 개수 제한이 없음 | 우선 출처, 중요도와 최대 개수를 지정 |
| 같은 소식이 반복됨 | 중복 제외 조건이 없음 | 이전 실행과 같은 사건은 제외하도록 지시 |
| 앱 자료에 접근하지 못함 | 연결 또는 권한이 만료됨 | 앱 연결 상태와 허용 범위 확인 |
| 변경 작업에서 멈춤 | 외부 변경에 승인이 필요함 | 결과를 검토하고 승인하거나 작업을 읽기 중심으로 조정 |

## 11. 실습 완료 기준

* 작업 목적, 실행 일정과 시간대를 확인했습니다.
* 출처, 선별 기준, 개수와 출력 형식을 지시문에 넣었습니다.
* 변화가 없을 때의 동작을 지정했습니다.
* Scheduled 화면에서 작업 상태와 다음 실행을 확인했습니다.
* 첫 실행의 링크, 날짜, 중복과 요약 품질을 검수했습니다.
* 오류가 생겼을 때 추정하지 않고 실패 원인을 보고하도록 했습니다.
* 외부 변경이 포함되면 승인 단계를 유지했습니다.

## 12. 핵심 정리

* 예약 작업은 반복되는 프롬프트 실행을 자동화합니다.
* 일회성, 반복과 모니터링 작업으로 설계할 수 있습니다.
* 실행 시간보다 무엇을 어떤 기준으로 처리할지가 더 중요합니다.
* 목적, 일정, 대상, 선별 기준, 출력 형식과 알림 조건을 명확히 합니다.
* 첫 실행을 검수하고 결과가 너무 넓거나 반복되면 지시문을 수정합니다.
* 자동 실행이 정확성을 보장하지 않으므로 중요한 결과는 사람이 확인합니다.
* 외부 변경은 필요한 권한만 사용하고 승인 단계를 유지합니다.

현재 예약 작업의 생성·관리 방식과 지원 범위는 [OpenAI Scheduled tasks 공식 가이드](https://learn.chatgpt.com/docs/automations)에서 확인할 수 있습니다.
